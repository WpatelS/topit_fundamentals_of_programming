### Часть 1. Режимы запуска

В интерактивном интерпретаторе Python было выполнено выражение:

```python
2 + 3 * 4
```

Результат:

```python
14
```

Затем это же выражение было записано в файл task_1.py. При запуске файла результат автоматически не отобразился.  

Причина такова: в интерактивном режиме Python после вычисления выражения автоматически выводит его значение на экран. При запуске .py-файла выражение вычисляется, но его результат не выводится автоматически.

Чтобы результат появился в терминале, выражение было изменено следующим образом:

```python
print(2 + 3 * 4)
```

Вывод программы:
```python
14
```

### Контрольный вопрос
***Почему байткод CPython нельзя считать машинным кодом процессора?***  

Байткод CPython нельзя считать машинным кодом процессора, потому что он является лишь промежуточным представлением программы и предназначен для выполнения с помощью своей виртуальной машины, то есть интерпретатора байткода. Машинный код содержит инструкции, которые непосредственно выполняются процессором, а байткод CPython такими инструкциями не является.

## Задание 2. Имена, объекты и сравнение

Исследовал следующую программу:

```python
a = 1000
b = a
c = int("1000")

print("Типы:", type(a), type(b), type(c))
print("Идентификаторы:", id(a), id(b), id(c))
print("a == b:", a == b) #True
print("a is b:", a is b) #True
print("a == c:", a == c) #True
print("a is c:", a is c) #False (В конце явно должен быть подвох. Не знаю с чем он может быть связан, возможно с тем, что переменная c создается через функцию int(), а не напрямую. Но это не точно. Нужно проверить.)
```
1. Текстовая схема связи между именами и объектами:  

    ```python
           _______
    a --->|       |
          | 1000  |
    b --->|_______|
           _______
    c --->|       |
          | 1000  |
          |_______|
    ```

2. Равенство значений и идентичность объектов  
    - **Равенство значений**   
        Оператор "==" проверяет, равны ли значения двух объектов.

    - **Идентичность объектов**   
        Оператор "is" проверяет, являются ли два выражения ссылками на один и тот же объект.

3. Изменил значение c в программе на None и добавил корректную проверку того, что c обозначает объект None:
    ```python
    c = None
    print(c is None)
    ```
    Результат:
    ```python
    True 
    ```
4. Был отдельно выполнен следующий код:  
    ```python
    first = "python"
    second = "py" + "thon"

    print(first == second)
    print(first is second)
    ```
    Результат:
    ```python
    True    # Потому что обе строки имеют одинаковое значение
    True    # сработал string interning в CPython.
    ```
    string interning - это оптимизация, при которой в памяти хранится только одна уникальная копия каждой строки, что ускоряет их сравнение и экономит память.

    Интернирование строк срабатывает не всегда. У этого есть определённые правила, но они зависят от реализации Python. Следовательно и оператор "is" не всегда будет выдавать True при сравнении двух строк с одинаковым значением.

5. Правило применения операторов "==" и "is":
    - Оператор == следует использовать, когда необходимо проверить равенство значений объектов.  

    - Оператор is следует использовать, когда необходимо проверить идентичность объектов, то есть являются ли два выражения ссылками на один объект.

### Контрольные вопросы:  

1. Создает ли инструкция b = a копию объекта?

    *Нет, она связывает имя b с тем же объектом, с которым уже связано имя a.*
2. Что возвращают type() и id()?
    *type() возвращает тип объекта, а id() - уникальное целое число, идентифицирующее переданный ей объект.*
3. Почему None принято сравнивать с помощью is, а числа и строки — с помощью ==?  
    *None является специальным объектом-синглтоном: в обычном Python существует один объект None, поэтому для него проверка с помощью 'is' или '==' будет иметь один и тот же результат. Для чисел и строк же обычно требуется сравнивать именно их значение, так что 'is' для этого не всегда подходит*
